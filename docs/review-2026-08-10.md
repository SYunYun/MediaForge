## 一、严重程度分级

### 🔴 必须修

**R1. `subs/media.py:64` — `locate_series` 的 "S" 前缀误判（已实证）**
```python
if c.name.upper().startswith("S") or c.name.lower() == season.lower():
    return str(c)
```
本意是"候选已经是季目录（名前缀 `Season 01`/`S01`）就直接返回"，但 `startswith("S")` 会命中**任何剧名以 S 开头的剧**。实测 `locate_series("Severance","Season 01")` 返回的是 `.../Shows/Severance`（剧根目录），而不是 `.../Severance/Season 01`。随后 `scan_episodes` 把整部剧所有季的 mkv 当成一个"季"平扫，`show = Path(season_dir).parent.name` 还会取到库根目录名。Severance、Stranger Things、Suits、Soul 等常见剧名全踩。
**修复**：季目录判定用专用模式（`re.match(r"^S\d+|^Season\s+\d+", name, re.I)`），并优先精确匹配 `season` 参数；把 `startswith("S")` 换成模式匹配，且命中季模式前先检查 `c / season` 子目录。**务必补单测**（见 B1）。

**R2. `cardigann/engine.py:359-360` — 原地修改 Definition 的 rows.selector（破坏纯函数/幂等）**
```python
if isinstance(spec.rows.selector, str) and "{{" in spec.rows.selector:
    spec.rows.selector = _template.render(spec.rows.selector, context)
```
把渲染结果写回 `spec.rows.selector`。同一 Definition 对象被二次 `search()`（不同 user_config / 不同调用方）时，`"{{"` 已消失，不再重渲染，且残留上次的上下文结果。TPB 的 `${{ if .Config.uploader }}...{{ end }}` 首渲后永久变 `$`。违背"派生不记忆"原则。
**修复**：渲染到局部变量 `rows_selector = _template.render(...)`，不动 `spec.rows`。

### 🟡 应该修

**Y1. `cli.py:216` + `feed/qbit.py:93,140` — `cmd_add` 只捕 `QbitError`，网络异常穿透成 traceback（已实证）**
`QbitClient.__init__→_login` 的 `self.s.post` 和 `_add` 的 `resp.raise_for_status()` 抛的是 `requests.exceptions.ConnectionError` / `HTTPError`，不是 `QbitError`。实测 qbit 连接拒绝时 `main(['add',...,'--json'])` 直接抛未捕获 `ConnectionError`，**违反"错误要响亮 + --json 契约"**（agent 拿不到结构化错误）。
**修复**：在 `QbitClient` 内把网络/HTTP 异常统一包成 `QbitError`（`_login`/`_add`/`torrents` 都包一层），或 `cmd_add` 补 `except requests.RequestException`。推荐前者（收口在客户端）。

**Y2. `subs/ledger.py:22-24` — `_key` 不做路径清洗，含 `/` 剧名直接 FileNotFoundError（已实证）**
```python
f"{show.lower().replace(' ', '_')}__{season.lower().replace(' ', '_')}"
```
实测 `update_episode("A/B",...)` 抛 `FileNotFoundError: .../a/b__season_01.json`（`/` 造成子目录穿越）。剧名极少含 `/`，但这是纯健壮性洞。
**修复**：`re.sub(r"[^a-z0-9_]+","_", ...)` 后再拼键。

**Y3. `cardigann/engine.py:336-338` — 路径段二次编码（已实证）**
只对 path 段逐段 `quote(seg, safe="")`，若渲染后的 path 已含 `%` 编码（sitelink 基址带 `%20`、定义里预编码、或关键词本身含 `%`），实测 `foo%20bar` → `foo%2520bar`，请求 4xx/404。当前已知三卡（yts/eztv/1337x）path 均无预编码字符，故未触发，但属潜伏坑。
**修复**：先 `urllib.parse.unquote(seg)` 再 `quote(seg, safe="")`，或检测 `%` 跳过已编码段。

**Y4. `cardigann/template.py:179-193` — 条件函数缺参无边界保护**
`eq`/`not`/`and`/`or` 在参数不足时（如 `{{ if eq .x }}`）直接 `IndexError`，而非干净的 `TemplateError`。畸形定义卡会崩掉整条搜索（虽被 CLI 逐索引器吞掉，但错误信息是裸 IndexError）。
**修复**：`_eval_cond` 内先校验 `len(cond)`，不足抛 `TemplateError`。

### 🟢 可选 / 代码质量

**G1. `cardigann/engine.py:61` `stripped_proxy_env` 是死代码**——定义、导出、被测试，但 `src/` 内零调用。`make_session` 用 `trust_env=False` 已解决代理污染，此函数无用武之地。要么真用上（作为显式剥环境的公共工具对外发布），要么删掉避免误导。

**G2. `subs/ass.py:67,89,133` — 三处 `open()` 未用上下文管理器**——循环读文件/写文件不显式 close，靠 GC 回收。应用 `with open(...)`。`shift_ass_file` 的写路径尤其应该 `with` 保证 flush。

**G3. `subs/ass.py:126` `shift_ass_file` 非幂等且无测试**——对同一文件多次调用会叠加平移（`cue.start` 是原始值，第二次等于双倍平移）。docstring 只写"由调用方保证符号"，但没防重复调用。本函数是唯一能改字幕文件内容的写路径，却是**零测试**（见 B3）。

**G4. `subs/inspect.py:91` 硬编码临时路径 `/tmp/mf_subs_sdh.srt`**——非并发安全、跨平台不稳、跑完留文件。建议 `tempfile.NamedTemporaryFile` 或随 mkv 同名。

**G5. `feed/qbit.py:58` `to_magnet` 的 `dn=` 裸拼剧名**——含空格/`&` 的 name 未 URL 编码，magnet 可能被 qbit 解析异常。用 `urllib.parse.quote(name)`。

**G6. README 已过期**——roadmap 表里 subs 仍标 ⬜、hunt 标 "116 tests"；实际 subs 已实现且总测试 131。建议同步 README 状态与计数。

**G7. `engine.py:243` `_coerce_int` 对"1.5 GB"这类人类可读 size 返回 None**——HTML 卡（如 eztv 实卡）size 常是 "1.5 GB"，导致 size=None → 体积带不打分。属已知局限，但值得在 docs 明示或加个解析器。

**G8. `inspect.py` `judge` 的 `end_short` 硬编码 `-0.5`**，而相邻的 ok 区间用了命名常量 `START_OK_LO`。建议统一抽常量。

## 二、测试盲区（覆盖声称 vs 实际）

覆盖声称（131 全绿）**属实**，但"绿"≠"覆盖关键路径"。抽查发现四个实质性盲区：

**B1. subs 模块的判定/扫描/写路径几乎全裸**（最严重）
- `test_subs_inspect.py` **只测了纯函数 `judge()`** 的 6 个分支。而 `inspect_episode`、`_match_sdh`（全表扫描+时间窗匹配）、`inspect_series`、`media.locate_series`、`scan_episodes` **全部没有测试**。这正是 R1（S 前缀 bug）能活着进代码的原因——`locate_series` 一条测试都没有。
- `test_subs_ass.py` 测了 `ts2sec/sec2ts/parse_srt/parse_ass/norm_tokens`，但 **`shift_ass_file`（唯一的写文件路径）和 `extract_eng_track`（调 ffmpeg）零测试**。
- `test_subs_ledger.py` 测了 roundtrip/merge/missing，但 **`_key` 的清洗（Y2）没测**。

**B2. cardigann 模板函数调用（`_Call`）未测**——`test_template.py` 覆盖变量/if/eq/and/or/not，但 `{{ join .Categories "," }}` 这类函数调用渲染（`_maybe_call`/`_eval_call`）**没有任何测试**。函数调用只在 filters.py 里作为滤镜测过，模板侧是另一条代码路径。

**B3. JSON rows 抽取路径无确定性单测**——`_json_rows`、相对路径拼 sitelink、`$` 根选择器、path URL 编码（Y3）这些核心逻辑，只被 `test_yts_e2e.py`（网络，不可达即 skip）覆盖，**没有 mock 的确定性单测**。`test_engine_html.py` 只测了 HTML 分支。一旦 YTS API 抽风，JSON 路径回归无人发现。

**B4. `cmd_add` 的非 QbitError 失败路径未测**——`test_cli.py` 只桩了抛 `QbitError` 的分支，网络异常穿透（Y1）没测。

**建议**：优先补 `media.py` 的 `locate_series/scan_episodes` 单测（用 tmp_path 构造目录树，能直接抓回 R1/Y2），再补 `_json_rows` 的 mock 单测和 `shift_ass_file` 单测。

## 四、总评：能不能作为继续开发的地基？

**能，但有两个前提。**

hunt/feed 这两块（Cardigann 解释器 + 打分 + qbit 幂等投喂）是**成熟合格的地基**：纯函数解释器、幂等设计、sitelink/相对路径/URL 编码等兼容墙都踩平并有测试护航，131 绿属实，README 里的设计原则在代码里有真实落地。subs 模块则**明显是"刚起步"的成熟度**——体检判定逻辑（`judge`）有测试，但真正会在生产跑的 `locate_series`/`_match_sdh`/`shift_ass_file`/`scan_episodes` 全裸，且已实证藏着一个对"以 S 字母开头的剧"必然误判的 bug（R1）。

**作为继续开发地基的充要条件**：
1. **先修 R1、R2 两个 🔴**（R1 是真实正确性错误，R2 是状态污染隐患），并把 B1 里 `locate_series/scan_episodes` 的单测补上——否则"subs 是自愈闭环"的承诺建立在一个没测过的扫描器上。
2. **把 Y1 收口**（QbitClient 统一包 QbitError），否则 agent 场景下 qbit 一抖动，`add --json` 就吐裸 traceback，违背项目最核心的"错误要响亮"。

在此之上，这份代码的架构、模块切分、幂等取向和测试纪律都足以支撑 hunt→get→organize→subs 的 daemon 化路线。**结论：可作地基，但要先补上 subs 的扫描/写路径测试并修掉 R1/R2，再谈继续铺楼。**
